    Registers

    What the interpreter models

    CHIP-8 is a tiny virtual machine from the 1970s. The interpreter keeps its whole state in a few arrays: memory, registers, a stack and the screen.

    0x000Interpreter and font512 bytes
    0x200Program ROM and working memory3,584 bytes, up to 0xFFF
    V0 to VF
    Sixteen 8-bit registers; VF is the flag
    I
    Address register
    PC
    Program counter, starts at 0x200
    Stack
    Return addresses for subroutines
    Screen
    64 × 32 pixels, one bit each

    Two bytes per instruction

    Every instruction is two bytes. The fields are pulled out with masks and shifts, then the high nibble picks the operation.

    uint16_t op = mem[pc] << 8 | mem[pc + 1];

uint8_t  x   = (op & 0x0F00) >> 8; // Vx
uint8_t  y   = (op & 0x00F0) >> 4; // Vy
uint8_t  n   =  op & 0x000F;
uint8_t  nn  =  op & 0x00FF;
uint16_t nnn =  op & 0x0FFF;

switch (op & 0xF000) { /* ... */ }

    A few of the instructions

    00E0Clear the screen
    1NNNJump to address NNN
    2NNNCall the subroutine at NNN
    00EEReturn from a subroutine
    6XNNSet Vx to NN
    8XY4Add Vy to Vx; VF holds the carry
    ANNNSet I to NNN
    DXYNDraw an N-row sprite at Vx, Vy; VF flags a collision

    What I built

    • Modeled the machine state: 4 KB of memory, sixteen 8-bit registers and a subroutine stack.
    • Decoded binary instructions with bitwise masking and shifts to implement arithmetic and control flow.
    • Implemented ROM loading and SDL2 graphics, input and audio, including the 64×32 display with XOR sprite collision detection.
    • Tested and debugged against CHIP-8 test ROMs.
    • Compiled the same C to WebAssembly with Emscripten so it runs on this page: the browser now drives the frame loop that SDL_Delay used to pace.

    Build and run

    Requires gcc, SDL2 and GNU make on Linux.

    make
./chip8 path/to/rom.ch8
